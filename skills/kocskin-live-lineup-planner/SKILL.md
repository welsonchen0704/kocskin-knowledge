# KOCSKIN 直播+1 排品規劃

## 0. 定位

把「庫存 ＋ 歷史銷售 ＋ 歷史組合」轉成一份可執行的排品建議表。
直播+1 不只是價目表——它是一場帶娛樂性的銷售節目：排品是骨架，互動機制是節奏和刺激。
Skill 負責：算數據、找衝突、攤開選項（含機制選項）。
Welson 負責：取向、錨微調尺度、機制挑哪幾種、定稿。
不得替 Welson 自動決定以上事項。

## 1. 需要的輸入（三類檔案，通常在「直播+1」資料夾）

1. **最新庫存表**（如 `秋雨庫存表_MMDD.xlsx`，sheet `BQY_INVENTORY`）
   - 只取「倉別=良品」的可用量，同 SKU 多批號要加總。
   - 記下快照日期，全程註明（R6 數字保鮮）。
2. **歷史組合表** `直播+1.xlsx`
   - 一場一個 sheet，sheet 名 = 民國式日期（如 260702）。
   - 「XXXXXX排品建議」sheet 是該場最終版；同名無後綴 sheet 多為清單/草稿。
   - 新場草案常是上一場排品建議的複製貼上——精修時務必檢查重複度。
3. **出貨資料** `koc_YYYYMMDD_order-N(直播+1信用卡/到付).xlsx`（sheet `秋雨退庫資料`）
   - 每列一個品項明細，一張訂單多列。

缺任一類 → 明講缺什麼，請 Welson 掛資料夾或補檔，不得憑記憶補數字。

## 2. 資料判讀的坑（每次都要記得）

- **信用卡檔的「訂單金額」全是 0**，只有到付檔有金額。真實營收大宗在信用卡端（歷史約佔七至八成），
  不可只加總到付檔就當全場營收；需要營收時用直播價回推或問 Welson 實際數字。
  客單價分析同理：只能用到付樣本估，要註明樣本侷限。
- **出貨檔日期 ≠ 直播日期**：出貨檔是直播後幾天出的（如 0707 出貨檔 = 260702 場）。對場次要用時間順序推斷並跟 Welson 確認。
- **品名跨場寫法不統一**（同品有多種寫法、有無前綴、數量後綴不同），跨場彙整一律用「商品貨號」正規化。
- 零星小檔（幾筆的 order 檔）多為補單，併回鄰近主場次。
- **人氣指標用「下單筆數」**（多少張訂單含該品）比總件數更能代表搶購熱度。

## 3. 分析流程

1. 庫存表 → 每 SKU 良品可用量總表；標記低庫存（開不了標的）與高庫存（必須消化的）。
2. 最近一至兩場出貨 → 各品項下單筆數排行：走量王（前 25%）、弱銷（<5 筆）。
3. 到付檔訂單金額 → 客單價分布（平均/中位數/P75/P90），供滿額送門檻反推。
4. 掃描 `直播+1.xlsx` 全部 sheet → 每 SKU「最後以正式標出場」是哪一場；
   長期未出場（>2 場）且庫存高者 = 生面孔候選，優先排入。
5. 與上一場排品建議逐標比對重複度，主動回報「完全相同」的標有幾個；
   同時比對上一場用過哪些互動機制，本場建議換不同的玩法。
6. 產出排品草案＋機制建議 → 核贈品/獎品跨標庫存衝突 → 對話提案 → Welson 確認 → 出 Excel。

## 4. 排品原則

- **錨保留、微調不換品**：驗證過的走量王/火車頭/壓軸保留，但數量、價格或贈品要調整，
  避免與上一場一模一樣（價格框架/折數區間維持一致）。火車頭（如安瓶）是全場價格基準，預設不動。
- **輪替**：長期未出場＋高庫存的品優先上場；連續出場且賣況平平的品輪休。
- **弱銷處理**：上場 <5 筆的品降役——轉贈品、進盲包、當抽獎獎品、或休一場。
- **贈品挑選**：優先挑「這次沒開標、庫存又待消化」的品；贈品也要核庫存夠不夠送。
- **限量組數由庫存反推**：可用量 ÷ 每組件數，再扣掉其他標（含贈品、盲包、機制獎品）對同 SKU 的占用。

## 5. 互動與娛樂機制庫（選配層，全部出自歷史場次實戰）

每場挑 2–3 種，不要全上（節奏會亂）。跟 Welson 用選擇題確認挑哪幾種。

| 機制 | 玩法 | 歷史範例 | 位置 |
|---|---|---|---|
| 秒殺限量 | 開場超低折限量標，先搶先贏 | 各場開場 0.36–0.40 折 | 開場 |
| 留言/分享抽 | 留關鍵字抽購物金，開播前 10 分鐘先抽拉人氣 | 250408：購物金150×10名 | 開場前 |
| 信任標 | 開高價 → 現場「凹價」降價 → 最後再加贈 | 250109：洗面乳 2940→2500+贈 | 開場/中段 |
| 轉盤遊戲 | 下單即轉盤抽紅包折抵 | 250109：0/88/188/288 | 中段喚醒 |
| 抽籤定價 | 先抽籤決定該標成交價再開搶 | 230922：玫瑰乳液 600/800/1000 | 中段高潮 |
| 抽籤加碼 | 下單抽加碼贈品或再折 | 260506：抽安瓶/再折100/200/謝謝惠顧 | 中後段 |
| 滿額階梯送 | 全場累計滿額換檔次贈品 | 240523：滿3000/4000/5000 三階 | 全場貫穿 |
| 盲包 | 多件組隨機內容壓軸，可加隨機彩蛋 | 歷史下單筆數常居第一 | 壓軸 |

設計規則：
- **滿額送門檻由客單價分布反推**：門檻設在中位數與 P75 之間，讓中間客群「再加一標就到」；
  第二、三階往 P90 推。三階採遞增贈品價值，並沿歷史慣例明講「滿額不累贈」（或明定累贈規則）。
  範例（中位數約 3,000、P75 約 4,500 時）：滿 4,000 / 滿 6,000 / 滿 8,888 三階。
- **抽籤定價標只挑毛利空間大的品**：最低檔成交價也要保本，先算好每一檔的折數與毛利再開玩。
- **獎品來源與贈品邏輯一致**：從「這次沒開標、待消化庫存」挑，並全部納入庫存衝突核算、估用量。
- **現金折抵檔位沿用歷史慣例**（0/88/188/288 或 再折100/200/謝謝惠顧），含「謝謝惠顧」檔可控成本。
- 機制屬促銷贈獎活動：最大獎價值留意公平交易法贈獎額度規範；對外預告文案仍須過 R2 合規審查。

### 主持陣容與戲劇張力（機制的表演層）

直播由 2–3 位主持人搭檔，用演戲、做梗強化價格與組合的張力。排品時要把「戲」一起想：

- **慣用戲路分工**（可依當場人員調整）：一人扛「老闆/成本方」（捨不得、喊賠錢）、
  一人站「觀眾方」幫大家凹價加碼、第三人補刀與控留言節奏。價格張力來自角色衝突，不是單口報價。
- **標的角色要配戲**：作價標＝價值鋪陳劇（先把牌價故事講足再現場砍）；信任標＝凹價戲
  （歷史範例 250109：開 2940 → 凹到 2500 → 最後再加贈）；秒殺＝倒數逼單；盲包＝開箱驚喜；
  轉盤/抽籤＝遊戲主持段。並非每標都要演，一場安排 3–5 個「戲點標」即可，其餘快節奏帶過。
- **排品提案時附「戲點備註」**：對戲點標各給一句衝突點/梗點建議（例：這標老闆會翻臉、
  這標主持幫觀眾凹到加送 X），供主持人備稿參考；最終演法由主持團隊自由發揮。
- **口頭加碼要預留庫存**：演戲中臨場「再加送」是最常見的庫存衝突來源。戲點標若預期會凹出
  額外贈品，排品時先把加碼品項與數量預留進庫存核算；主播口徑（價格/贈品）以排品表為準。
- 演出台詞同樣不得踩 R3 禁語（療效、最、唯一、保證等）；直播雖即時，戲點備註與腳本裡
  也不要寫入禁語，避免主持人照唸出事。

## 6. 計算慣例

- **總價值 = 正裝價值**：同品項「買X送X」全部計入；跨品項贈品一律不計入。
- **單瓶牌價一律由歷史場次總價值回推**（總價值 ÷ 件數），不得虛構或憑記憶；
  歷史找不到牌價 → 標「待查」問 Welson 或查 Notion V2，不得自行估價。
- **折數 = 建議價 ÷ 總價值**。參考區間：開場秒殺約 0.36–0.40、作價標約 0.33–0.44、
  走量標約 0.5–0.7、火車頭約 0.44。
- 排品表「庫存」欄：有確定數字才填（任選組合填合計並備註拆分），多品項盲包留空白。

## 7. 節奏模板（16–18 標＋機制穿插）

開場前：留言抽（選配，先炒熱）
開場：秒殺限量 2–3 標（約 0.39 折，引流）
中段：火車頭作價 1 標 → 走量標穿插作價/限量標（高庫存必清品放中段前半）；
　　　中段過半處放一個機制高潮（轉盤/抽籤定價/抽籤加碼）喚醒停留
尾段：囤貨標 → 人氣限量 → 壓軸（＋盲包選配）
全場：滿額階梯送（選配）貫穿，主播隨時報「你再加一標就到門檻」；戲點標 3–5 個分散於作價/信任/壓軸位

## 8. 產出

1. 先在對話給提案：完整排品表＋每標理由＋庫存衝突說明＋機制建議（含門檻/獎項/預估成本）
   ＋待 Welson 拍板事項（用選擇題問）。
2. 確認後出 Excel，欄位比照歷史格式：
   `庫存(快照日期)｜標數｜時段｜標數（角色，含贈品寫法）｜商品名稱｜建議價格｜折數｜總價值/贈品不算入｜備註`
   表尾加「互動機制」區塊：機制名稱、觸發條件/門檻、獎項內容、預留庫存（比照 260506 抽籤加碼列的做法）。
   檔名 `{場次}排品建議_vN.xlsx`，存回直播+1資料夾。
3. 寫檔後 read-back 驗證（R7），回報實際寫入內容。

## 9. 紅線對接（引用工作憲章，衝突時以憲章為準）

- R5 停售品／未販售紅線品：任何場合不得排入、不得當贈品或獎品。名單唯一正本＝
  `kocskin-compliance-check/references/brand-rules.md`〈一、停售商品〉（含 2026-07-13／14 停售批次）
  ＋Notion V2 `SKU狀態` 即時值；相似名在售品防混淆規則見正本，勿混淆誤殺。
- R6 庫存為快照數字：註明日期；開播前一天建議重拉庫存表核限量組數（低庫存標尤其要核）。
- 本 skill 產出為內部排品表，非對外文案；直播預告貼文、機制活動辦法等對外內容，
  另走 kocskin-post-writer 與 kocskin-compliance-check 流程（R2）。
