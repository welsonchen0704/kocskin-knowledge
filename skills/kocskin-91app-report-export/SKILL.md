# 91app 月報表匯出（catch-data）

用瀏覽器工具，匯出 KOCSKIN克麗詩黛在 91APP 後台的完整月報表組合，
共三大類、16 個檔案：固定的兩份當月報表（報表一、二），加上「營運趨勢報表」底下
14 個近30天分頁（報表三）。**三者是預設的完整範圍，觸發這個 skill 就是三個都做**，
不需要使用者額外指名報表三。本 skill 記錄的等待秒數、UI 狀態變化、座標位置都是
實跑觀察所得，不是憑空估計——偏離這個流程（例如提早點擊、跳過等待）容易匯出失敗
或匯出空資料。

## 瀏覽器工具對照（2026-09-14 補）

本 skill 的步驟原以 **Claude in Chrome** 實跑驗證，工具名以該組為準。若 session 的預設瀏覽器是 **Claude 內建瀏覽器**（Claude_Browser），工具對應如下，流程不變：

| 動作 | Claude in Chrome | 內建瀏覽器 |
|---|---|---|
| 列出分頁／抓 tabId | `tabs_context_mcp` | `tabs_context` |
| 開新分頁 | `tabs_create_mcp` | `tabs_create`（或 `preview_start` 帶 url） |
| 關分頁 | `tabs_close_mcp` | `tabs_close` |
| 導航 | `navigate` | `navigate` |
| 截圖／點擊／三連點／輸入 | `computer` | `computer` |
| 找元素 | `find` | `find` |
| 讀頁面文字 | `get_page_text` | `get_page_text` |

兩點注意：
- **下載行為只在 Claude in Chrome 驗證過**（檔案落在 Chrome 預設下載目錄）。內建瀏覽器的下載落點尚未實跑確認，第一次用內建瀏覽器跑時，先只做報表二（單一檔案）確認檔案到哪裡、使用者能否拿到，再跑完整 16 檔；若拿不到檔案，改用 Claude in Chrome。
- 91app 登入狀態兩個瀏覽器不共用；內建瀏覽器第一次進站可能需要使用者登入。

## 固定參數

- 商店：KOCSKIN克麗詩黛，`shopId=40757`
- 查詢區間：當月 01 日 ～ 執行日的「前一天」（例：8/13 執行 → 2026/08/01 至
  2026/08/12）。這是因為 91app 資料只統計到查詢當日的前一天，當天數字不會包含在內。
- 日期輸入格式：`YYYY/MM/DD`
- 匯出設定一律用系統預設值，不要更動
- 假設使用者 Chrome 已關閉「下載前先詢問儲存位置」——正常情況下不需要詢問下載路徑，
  直接匯出即可。如果瀏覽器仍跳出系統層級的儲存路徑視窗，那是作業系統視窗，
  無法用工具操作，需請使用者自行選目錄並按儲存（不要嘗試用座標亂點去關閉它）。

## 共通前置動作：收合左側選單

兩個站台（analytics.91app.com、store.91app.com）進站後，左側導覽列預設是展開的，
會蓋住報表的控制項（下拉選單、匯出鈕、查詢區間欄位）。每次進站後，先點左下角的
收合按鈕（畫面最左下角、約座標 x=195 / y=691 的箭頭圖示）收合選單，收合後圖示會
變成 `>|`。這一步不做，後面依賴座標的點擊會全部失準——所以務必排在最前面，
且用截圖確認選單已經收合再繼續。

## 報表一：商品銷售排行榜（analytics.91app.com）

1. 前往 `https://analytics.91app.com/#/analytics/productAnalytics?shopId=40757`
2. 等待載入。這個站初次進入會先顯示 91APP logo 動畫，約需 3～5 秒才會出現主畫面，
   截圖確認主畫面出現後再繼續。
3. 收合左側選單（見上）。
4. 點左上角的報表下拉選單（預設顯示「自訂報表」）。選單項目依序是：
   自訂報表 / 商品銷售排行榜 / 商品分類銷售統計表 / 收藏／購物車商品報表。
   點選「商品銷售排行榜」。
5. 等頁面重載約 3 秒。用網址列確認已切換成功：URL 會帶上
   `reportTemplateKey=productSalesRanking`，畫面上「自訂欄位」旁會出現數字 6，
   排序方式會變成「已售商品數量」。
6. 點右上角「查詢區間」，開啟「報表資料顯示範圍」視窗。視窗內的時間區間下拉
   應為「自訂」，並會提示「查詢時間區間不得超過 366 天」。
7. 結束日通常已經預設為前一天，確認一下即可，不用動它。
   起始日欄位：三連點（triple_click）全選欄位內容 → 直接輸入 `YYYY/MM/DD`
   （當月 01 日）。輸入後日曆會自動跳到該日期並標亮，用截圖確認。
8. 按日曆右下角「OK」關閉日曆，再按視窗下方「套用」。
9. **關鍵等待點——不要提早點匯出**：套用後資料載入可能需要 15～20 秒。
   這段期間「總共筆數」會顯示 0、「匯出」按鈕呈灰色（不可點）、畫面上方會顯示
   「載入中 請稍等」。必須等到「總共筆數」更新成實際數字、且「匯出」按鈕轉為
   綠色，才能進行下一步。若載入超過 30 秒仍為 0 筆，先重新整理頁面再重跑
   步驟 6-9，不要直接硬點匯出。
10. 按「匯出」→ 開啟匯出設定視窗，保持預設值（匯出範圍為「全部筆數：N 筆」、
    匯出格式為「使用 Windows Excel 開啟 (UTF-8 BOM)」）→ 按「確認」。
11. 匯出中，按鈕會變成灰底「處理中」文字，畫面上方顯示「匯出中 請稍等」，
    約 5～8 秒後按鈕會恢復成綠色「匯出」，這就代表匯出完成。
    「匯出完成」的 toast 提示可能一閃即逝、來不及截到圖，**只要按鈕已經恢復成
    綠色就視為成功，絕對不要因為沒看到 toast 就重新按一次**——重複點擊會產生
    重複檔案。
12. 記錄回報用的數字：「總共筆數」，以及表格最上方「重複合計」列的
    已售商品數量 / 訂單數(TS) / 訂單金額(TS)。

## 報表二：商店銷售統計表（store.91app.com）

1. 前往 `https://store.91app.com/Report/SalesStatisticsDataByDateList?shopId=40757`
2. 收合左側選單（見上）。
3. 時間區間有兩個可輸入欄位（placeholder 為「選擇或輸入開始日期／結束日期」）。
   頁面預設區間是「前一個月同日 ～ 前一天」，所以**通常只需要改起始日**為
   當月 01 日，結束日通常已經是正確的（前一天），先確認一下再決定要不要動。
   改法一樣是三連點全選欄位內容後直接輸入 `YYYY/MM/DD`。
4. 國家/地區欄位保持「不顯示」（頁面預設值），不要更動。
5. 按「查詢」，往下滾動確認每日資料表已經出現，並確認表格最下方有「小計」列。
6. 按「匯出資料」**一次**。這個頁面的匯出沒有任何畫面提示、也沒有可觀測的網路
   請求會顯示出來，這是正常現象，**不要因為看不到回饋就再按第二次**——那樣會
   產生重複檔案。判斷「已完成」的依據就是「已經按過一次」，不需要等待其他訊號。
7. 記錄回報用的數字（小計列）：購物車筆數 / 主單筆數 / 訂單筆數 / 商品數 /
   商品金額 / 折扣金額 / 訂單金額(折扣後) / 取消單筆數與金額 / 退貨結案 /
   淨銷售額 / 成本。

## 報表三：營運趨勢報表（store.91app.com，預設就要做，14 個分頁）

**這不是選配，是預設範圍的一部分**：使用者說「抓報表」「跑月報」「catch-data」時，
報表三跟報表一、二一樣要主動做完，不用等使用者額外指名分頁。這個頁面底下每個
分頁點「匯出報表」的行為，跟前兩份報表完全不同：不會跳匯出設定視窗、也不會直接
下載，而是彈出一個**新分頁**，是 91app 串接的 Tableau 原生「查看數據」視窗，要在
那個彈出分頁裡再點一次連結才會真的下載。

### 頁面結構

網址：`https://store.91app.com/PerformanceReport/OperationTrends?shopId=40757`

頁面上方有「數據類型」四個單選鈕：營運數據／會員數據／活動數據／服務數據，切換
後下面的分頁列會跟著換。**預設範圍固定是以下 14 個分頁**（已實際跑過確認可用，
每次執行都做這 14 個，不多不少）：

- **營運數據**（5 個，分頁列有「近30天／近1年」切換鈕）：總體營運成效、
  新舊客營運成效、Web/APP營運成效、Web/APP新舊客營運成效、營收趨勢報表。
- **會員數據**（5 個）：會員成長趨勢、實際交易人數與佔比、APP新開啟數
  （這三個**有**近30天／近1年切換鈕）；會員留存率、NAPL模型（這兩個**沒有**
  切換鈕——月度 cohort／12個月回溯的固定邏輯報表，不受「近30天」規則管，直接
  點匯出報表即可，見下方例外處理）。
- **活動數據**（4 個，有近30天／近1年切換鈕）：折扣活動成效、滿額贈成效、
  折價券成效、APP推播。

以下**不在預設範圍內**，除非使用者明確加點才做：營運數據「更多報表」下拉選單裡的
「各裝置流量與營收比較」；服務數據整個分類（平均出貨天數、取消率與退貨率、
Web/APP取消率與退貨率、取消原因、退貨原因——這個分類沒有近30天/近1年切換鈕，
且尚未實跑驗證過完整行為，貿然預設納入有匯出到錯誤區間或空資料的風險）。

**這個頁面不會被左側選單蓋住**，不需要做「收合左側選單」那個步驟（跟報表一、二不同）。

### 單一分頁的匯出流程

1. 點對應的「數據類型」單選鈕（若還沒在正確分類）。
2. 點對應的分頁名稱（分頁列會跟著數據類型變動，每次切換數據類型後最好用
   `find` 工具找分頁而不是背座標，因為 tab 列的位置和寬度每個分類都不一樣）。
3. 若該分頁有「近30天／近1年」切換鈕：正常情況下切分頁後「近30天」會自動維持
   選取狀態（深色底），確認一下即可，不用手動點。若該分頁**沒有**這兩個按鈕
   （目前已知：會員留存率、NAPL模型；服務數據全系列），代表這個報表的區間是
   固定邏輯決定的，不套用近30天規則，直接跳到下一步。
4. 點綠色「匯出報表」按鈕。**不會有匯出設定視窗**，瀏覽器分頁群組裡會多一個新分頁，
   標題是「查看数据」，網址是 `tableau.91app.io/vizql/.../viewData/...`。用
   列分頁工具（`tabs_context_mcp`／`tabs_context`）抓新分頁的 tabId，切過去操作。
5. 新分頁裡有兩個子分頁：「摘要」（依日期彙總，對應畫面上圖表的資料）與「完整數據」
   （逐列原始明細，依 UserType×訪客類型×購買狀態等維度細分）。**預設停在哪個
   子分頁不固定**（實測有時候是完整數據、有時候是摘要），每次都要先截圖確認，
   如果不是「完整數據」就手動點過去（除非使用者特別要摘要）。畫面上方「顯示前
   N 行」只是預覽筆數上限，不影響下方下載連結抓到的完整資料。
6. 點「完整數據」分頁上方的「將所有行下載為文本文件」連結，觸發下載。**這個下載
   跟報表二一樣沒有任何畫面回饋**（不會變灰、不會跳 toast），點一次就視為完成，
   不要重複點擊，也不用等待任何訊號。
7. 下載完成後，把這個 Tableau 彈出分頁關掉（`tabs_close_mcp`／`tabs_close`），切回原本的
   「營運趨勢報表」分頁，才能繼續下一個分頁的匯出（彈出分頁留著會越開越多，
   之後步驟用列分頁工具找新分頁會抓錯）。
8. 換下一個分頁重複步驟 2-7，直到預設範圍的 14 個分頁都跑完。

### 例外處理（報表三專屬）

- 每個分頁點「匯出報表」都會產生一個**新的 Tableau workbook**（網址裡的
  `OSM_A01`／`OSM_B03`／`OSM_C02` 之類代號每個分頁不同），不是同一份資料換分頁——
  所以每個分頁都要重新走一次步驟 4-7，不能只做一次下載就套用到其他分頁。
- 沒有「近30天／近1年」切換鈕的分頁（會員留存率、NAPL模型、服務數據全系列），
  不要嘗試去找或模擬這兩個按鈕，直接點匯出報表即可；回報時要跟使用者說明這幾份
  的區間是系統固定邏輯決定，不是「近30天」。
- 這裡沒有像報表一那樣「總共筆數」或「重複合計」列可以唷出來回報，資料是逐列
  明細，不做逐筆彙總朗讀。
- 下載觸發後的實際檔名由瀏覽器/Tableau 決定，本 skill 尚未確認固定命名規則，
  跟使用者回報時只需提醒到下載目錄確認檔案，不用猜測檔名。
- 若使用者要求「全部都要」「連服務數據也要」之類超出預設 14 個分頁的範圍（如
  更多報表選單裡的各裝置流量與營收比較、或整個服務數據分類），要主動跟使用者
  確認才擴大範圍，不要自行納入——這些還沒有實跑驗證過完整行為。反過來，若使用者
  沒有特別說要精簡，預設就是 16 個檔案全做，不要因為嫌麻煩自行省略報表三。

## 回報格式

三份報表（共 16 個檔案）都匯出後，跟使用者回報：

報表一、二：

- 各報表實際查詢的區間（起訖日期）
- 各報表的總筆數／小計等關鍵合計數字（見上面兩節「記錄回報用的數字」）

報表三：

- 依數據類型分組列出實際匯出的 14 個分頁名稱（營運數據5／會員數據5／活動數據4）
- 不逐筆列數字，資料是逐列明細不做彙總朗讀，只需確認 14 個檔案都已下載
- 若有分頁是「近30天」以外的固定邏輯（會員留存率／NAPL模型），要註明這幾份
  的區間定義跟其他分頁不同

最後：

- 總計檔案數（正常情況下是 16 個），提醒使用者到瀏覽器預設下載目錄確認檔案
  數量是否都在
- 固定附上以下兩則提醒：
  1. 91app 資料只統計到查詢當日的前一天，當天（執行日當天）的數字不會包含在內。
  2. 商品銷售排行榜報表為 Beta 版，數據僅供行銷觀測參考，不建議作財務用途——
     財務相關數字以商店銷售統計表為準。

## 限制與例外處理

- 商店銷售統計表的查詢區間最長 1 個月，若使用者要求跨月區間，要分次查詢、
  分別匯出。
- 商品銷售排行榜查詢區間上限 366 天。
- 兩份報表的匯出動作都**不可重複點擊**：報表一用「按鈕由處理中恢復成綠色」
  判斷成功；報表二用「已經按過一次」判斷完成，即使沒有畫面回饋也不要重按。
- 若資料載入超過 30 秒仍顯示 0 筆，先重新整理頁面再重跑查詢步驟，不要直接
  點匯出（會匯出空檔案或連到舊資料）。
- 若瀏覽器跳出系統層級的「選擇儲存位置」視窗，這是作業系統視窗，無法用工具
  操作，明確告訴使用者需要自己選目錄並按儲存。
