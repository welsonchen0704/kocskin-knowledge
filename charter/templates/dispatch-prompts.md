# 派工 Prompt 模板（五型）
版本：2026-07-03。用法：複製對應模板，填〔〕，整段作為 subagent prompt。
subagent 是全新 context：所有路徑、背景、已定決策都要填進去，不可省略。
每型都內建三件套：目標與動機／驗收條件／回報格式。

---
## T1 搜尋／掃描（建議 model: haiku；理解型搜尋用 sonnet）
目標：在〔範圍：目錄/repo/Notion DB/網站〕找出〔具體目標，例：所有出現「美白」二字的檔案〕。
動機：〔為什麼找，例：無文號 SKU 全面改詞前先盤點曝險面〕。
做法限制：只讀不寫；逐一列出，不判斷不修改。
驗收條件：
- 每筆結果含〔檔案路徑:行號 / Notion 頁面URL / 網址〕與前後各一行上下文
- 明列已掃描範圍與跳過範圍（及跳過原因）
- 零結果也要回報「已掃 X 個檔案，0 命中」
回報格式：清單，每筆一行；總結一句話；不貼原始檔全文。

## T2 實作（建議 model: sonnet）
目標：〔要做出什麼，例：新增一支 script 把 .srt 簡轉繁並輸出到 out/〕。
動機：〔用途與使用者，例：短影音 pipeline 的合規硬需求，用 opencc〕。
已定決策（不可推翻）：〔例：一律繁中；輸出路徑 out/；沿用現有 ffmpeg 流程〕。
輸入材料：〔路徑清單、範例輸入〕。
驗收條件：
- 用〔指定測試輸入〕實跑成功，貼執行輸出
- 邊界情況〔例：空檔、非UTF8〕的行為已定義並測過
- 不改動〔明列禁區檔案〕
回報格式：改了哪些檔（路徑:行號範圍）、實跑輸出、已知限制；程式碼落檔不貼回。

## T3 重構（建議 model: sonnet；跨檔大改用 opus）
目標：把〔對象〕從〔現狀〕改為〔目標結構〕，行為不變。
動機：〔例：規則散在三處造成不同步，收斂到單一來源〕。
安全繩：改前先備份到〔backup 路徑〕；行為驗證方式＝〔測試指令/對照樣本〕。
驗收條件：
- 備份存在（回報路徑）
- 重構前後〔驗證方式〕結果一致，貼比對
- 舊位置留下指向新位置的一行說明，不留重複內容
回報格式：異動清單（檔:行）、驗證比對結果、發現但未處理的問題另列。

## T4 研究（建議 model: sonnet；需綜合判斷用 opus）
目標：回答〔具體問題，例：91APP 是否支援 X API，官方文件怎麼說〕。
動機：〔這答案會拿去做什麼決策〕。
來源要求：優先官方文件/一手來源；每個結論附來源URL與存取日期；
查不到就寫「未查到」，禁止推測補齊。
驗收條件：
- 結論分「確定（有來源）／不確定（來源衝突或間接）／未查到」三層
- 至少〔N〕個獨立來源交叉（重大決策題）
回報格式：先一段結論，後列來源清單；長摘錄落檔傳路徑。

## T5 審查（必用 fresh context；一般 sonnet、合規灰區 opus）
目標：審查〔產出物路徑〕是否通過〔標準：compliance-rules.md 四關＋品牌紅線／
或指定驗收條件清單〕。
動機：驗證不自驗——你沒有參與產出，請以挑錯立場閱讀。
做法限制：只審不改。每一關/每一條逐項給結論；攔下的項目引用原句並給改法建議。
驗收條件：
- 標準清單逐條有「通過/攔下」結論，無「大致OK」這種字眼
- 對原文至少引用〔N〕處以證明真的讀了（防敷衍）
回報格式：結論（過/不過）→ 攔下清單（原句→問題→改法）→ 低信心項另列。

---
## 通用尾段（每型都附加在 prompt 最後）
「若遇到本 prompt 未覆蓋的歧義：選保守做法並在回報中標註『歧義決策』；
若歧義涉及花錢、發布、刪除、合規 → 不要做，回報請示。
回報上限預設 300 字（可調）＋清單；長內容一律落檔傳路徑。」
（模板內其餘〔N〕為填空占位，派工時填實值，勿連〔〕一起送出；無指定則預設 N=2。）
